This fixes the former use of one rim-basis column. The [edge-on ring painter](https://github.com/physicsvigilante/conductor_sim/blob/caf496f54c3825adcab5615d214c8e11d4d24e5d/src/conductor_sim/source_geometry.py#L274-L289) now paints `center_uv ± projected_major_axis_uv`; it retains the original **81-point physical rim curve**. The [new tests](https://github.com/physicsvigilante/conductor_sim/blob/caf496f54c3825adcab5615d214c8e11d4d24e5d/tests/test_m25a_review_corrections.py) construct **five qualified x-axis ring planes**, including the adversarial 45° one, compare rim extrema with a separately parameterized world-space ring, and exercise face-on, ellipse and degenerate 2×2 *mathematical* controls without claiming a face-on axial trajectory. I separately stress-checked the proposed eigenvalue/eigenvector formula against NumPy SVD for **10,000 deterministic random genuine 3-D ring/screen-plane projections**: maximal relative major-semiaxis discrepancy **8.76e-16 of radius**, with no contradictory result. This last check is a separate arithmetic reproduction of the formula, **not** execution of an imported production package.

Crucially, the [current-head browser script](https://github.com/physicsvigilante/conductor_sim/blob/caf496f54c3825adcab5615d214c8e11d4d24e5d/tools/check_m25a_source_geometry.py) creates **two new native-integrated scenarios**, `tilted-rings` (driven M24b) and `tilted-event-rings` (conservative M24a), using the actual source ring axis, `R=0.3 m`, and authored plane normal `(0,1/√2,1/√2)`. This is not a DOM-only or edited-after-the-fact HTML assertion.

## F-02 — RESOLVED: the radial slice boundary is physical, not a motion-tolerance extension

The [radial branch](https://github.com/physicsvigilante/conductor_sim/blob/caf496f54c3825adcab5615d214c8e11d4d24e5d/src/conductor_sim/source_geometry.py#L153-L178) now distinguishes:
- **Strict outside** `|h|>R`: `omitted-out-of-plane`, no bounds and no falsely drawn slice;
- **Exact tangent** `|h|=R`: explicit `slice-tangent`, zero radius and a [distinct point glyph](https://github.com/physicsvigilante/conductor_sim/blob/caf496f54c3825adcab5615d214c8e11d4d24e5d/src/conductor_sim/source_geometry.py#L255-L268);
- **Strict inside** `|h|<R`: genuine positive cross-section `√((R−|h|)(R+|h|))` for either sphere or shell.

The [six typed regressions](https://github.com/physicsvigilante/conductor_sim/blob/caf496f54c3825adcab5615d214c8e11d4d24e5d/tests/test_m25a_review_corrections.py) instantiate real `TestChargeMotionSpec` models for sphere and shell with `R=5e-12 m` and `h=4e-12, 5e-12, 8e-12 m`, respectively. The inside slice has `3e-12 m` radius, tangent has a one-point bound, and outside is omitted. Those examples remain within the unchanged motion-plane numerical qualification tolerance, so the correction separates physical geometry from solver tolerance as required. The source field, charge guard and qualification logic are unchanged. These are **CI-executed Python regressions**, not a separately re-run local package test or a new Chromium tangent screenshot.

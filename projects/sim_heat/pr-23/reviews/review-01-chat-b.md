## Findings

**F-01 — minor; source relation / future same-run identity policy.**

- **Source:** [build_compare_index.py:71-83](https://github.com/physicsvigilante/sim_heat/blob/439c02ae3157f01c8ccc7ab5eb58297af0c17d92/viewer/network/tools/build_compare_index.py#L71-L83); [compare_core.mjs:22-33](https://github.com/physicsvigilante/sim_heat/blob/439c02ae3157f01c8ccc7ab5eb58297af0c17d92/viewer/network/compare_core.mjs#L22-L33).
- **Input / independently reproduced observation:** Starting from the actual D2/D2-K2 index and original case objects, consistently repin the successor's run ID, artifact ID and original ZIP digest to the baseline's, leaving a *different* archive entry. The exact fetched JS validators accept this logically different slot. They also accept a successor executed-commit field of forty zeroes when **both the source-pair record and supplied case object are repinned**. The Python source-relation function likewise does not compare the commits. Conversely, the exact same output slot is rejected, and the same artifact with inconsistent run/ZIP is rejected. These are **isolated validator probes**, not a fully repinned catalog/browser or executed native artifact.
- **Expected / significance:** It is correct to allow distinct result slots in one genuine run/artifact without demanding two separate runs. But the meaning of “compiledSourceCommit” for a shared run should be explicit: the existing archived native attempt records it as GitHub's single GITHUB_SHA, while a future specialized workflow could in theory compile per-slot inputs from differing commits. Internally matching metadata alone cannot resolve this, and the present actual pair has distinct authentic runs/commits.
- **Confidence / evidence:** High for the exact JS validator behavior; high for the static Python condition; **not** evidence of an exploit of the catalog SHA gate or external GitHub authentication. **Recommendation:** Before admitting a real same-run multi-slot pair, add a test for divergent executed-commit fields and either enforce one workflow SHA per run or document and externally attest any intentional per-slot commit semantics. **Non-blocking for existing pair.**

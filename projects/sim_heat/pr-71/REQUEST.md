## Intended educational feature

A teacher may now compare **two preexisting, separately admitted H1 source studies** in a single read-only loopback workbench, for example:

~~~sh
python -B tools/authoring_workbench.py h1/cases/D2/study.json --root h1/cases \
  --compare h1/cases/D2_K2/study.json
~~~

The actual D2 baseline and D2_K2 revision have **authored** rod.k thermal conductivity 100 vs 200 W/(m K), not predicted fluxes or end temperatures. The workbench admits BOTH actual Modelica+study source files under the same trusted root and snapshots them **before opening any HTTP listener**. A new allowlisted JSON route supplies only the already-admitted scenario **display**; no raw source file route, write/upload endpoint or network service is opened. The original inspector remains available without --compare.

The page's comparison panel displays source assumptions and source-input differences, physical-port connectivity groups and rod endpoints, original attribution, model-name/regime and public-request changes; the teacher can switch between the two logical source graphs and inspect original inputs. Generated node_N indices and schematic graph positions are NOT physical geometry or stable topology identities. Browser imports of additional preview JSON are checked ONLY for structural, source-only display schema; the browser cannot independently authenticate uploaded Modelica/study bytes or owner/textbook provenance. The panel must not claim source fidelity certification merely by comparing two SHA strings.

**Mandatory semantic boundary:** Every public request stays not_computed. Output status describes SOURCE CHANGES ONLY. The comparison does not compute conductance laws, solve algebraic junctions, integrate body ODEs, claim heat flow/temperature results, invoke OpenModelica, use the old native reference bundle, or promote native/source/owner flags. Invalid/forged native-qualified source-only JSON, stale model/study SHA identities with contradictory display fields, invalid port topology and failed replacement inputs must refuse. When a currently displayed scenario is refused/replaced, the *old scenario's* graph/requests/details must not remain visible as if they represented the refused replacement; revert to the baseline.

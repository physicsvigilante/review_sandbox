## Source-level reasoning for the correction

At [app.mjs lines 120–151](https://github.com/physicsvigilante/sim_heat/blob/ae044ccad6bf58c171c9cc834b427b34cb892101/viewer/source_preview/app.mjs#L120-L151), every new scenario selection increments scenarioVersion; completed file text is admitted against its captured scenarioVersion and loadVersion. A valid source-only scenario with no current baseline is queued **only** while baselineLoading, under both generation tokens, with an explicit waiting status. Superseded or invalid input is refused/ignored without reusing an earlier graph. At [lines 104–117](https://github.com/physicsvigilante/sim_heat/blob/ae044ccad6bf58c171c9cc834b427b34cb892101/viewer/source_preview/app.mjs#L104-L117), admission renders the new baseline, ends baselineLoading and flushes the current queued scenario through setScenario/compareSourcePreviews, with a caught and visible comparison refusal if claimed model/study facts contradict. At [lines 154–165](https://github.com/physicsvigilante/sim_heat/blob/ae044ccad6bf58c171c9cc834b427b34cb892101/viewer/source_preview/app.mjs#L154-L165), each new baseline generation invalidates pending previous-scenario work and clears source graph/identity/requests before waiting. The common refusal functions clear queued selection and comparison state.

At [lines 167–195](https://github.com/physicsvigilante/sim_heat/blob/ae044ccad6bf58c171c9cc834b427b34cb892101/viewer/source_preview/app.mjs#L167-L195), initialScenarioGeneration is captured **before** awaiting TEACH_SPLIT3 and never reset after the fetch. Later server-default VARIANT can commit only if both the startup load token and the pre-fetch scenario token still match. This addresses the specific second review-02 reproduction rather than merely treating a later default response as the user's choice.

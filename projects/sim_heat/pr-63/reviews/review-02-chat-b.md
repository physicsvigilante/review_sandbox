## F-01 — MAJOR original hash/parse TOCTOU: CLOSED

**Location:** [corrected `compare.py`, `_original_inputs`](https://github.com/physicsvigilante/sim_heat/blob/6baba681ae1680e2fcae1ea8efbf0953afcb031b/qualification/h1_n2/compare.py#L63-L88).

The rejected head SHA-checked the first `Path.read_bytes()` result for original facts/model/study, then independently read facts and study **again** for JSON parsing. The corrected code captures three raw-byte snapshots, hashes **those exact buffers** against the fixed original SHA-256 constants, and parses only `snapshots["facts"]` and `snapshots["study"]`. It cannot parse a changed later filesystem read because no such later read is made by this function.

**Personally executed adversarial counterexamples:**

1. I patched `Path.read_bytes` to write an altered *real scratch file* immediately after returning the first, still-authentic bytes. Four independent mutation variants were **facts provenance**, **facts physical mass `T_Ridge.m`**, **original study analysis stop time**, and **Modelica file bytes**. The **old** implementation read facts twice, study twice, model once; for the first three mutations it returned post-check altered JSON (`original_json=False`). The **new** implementation read **facts once, study once, model once** for every variant, parsed the unchanged authenticated original JSON (`original_json=True`), and did not use the already-mutated on-disk bytes. The model-byte mutation similarly left the captured hash-checked model snapshot unaffected.
2. I reproduced the original **full API passing bypass**, not just an isolated parsing helper: after the first facts-file read, change scratch `provenance`; supply both reference bundles and receipts newly re-sealed to that forged provenance, together with the caller-chosen expected seals. **Old head returned `checks_passed`**, with two facts-file reads. **Corrected head returned `h1.model.Refusal: n2_comparison: primary reference facts are not the pinned original`**, with exactly one facts-file read. The scratch file was indeed mutated after that read; this was not a test that silently omitted the write.
3. Source inspection and the corrected author's before-read tamper test support the complementary boundary: changed bytes already present **at** the authenticated read fail the hardcoded digest. An after-read mutation cannot change the saved parsed snapshot. Neither the original facts/study files nor the fixed SHA constants were changed.

**Judgment:** F-01 fixed at the original-source byte-consumption boundary; no forged, freshly re-sealed provenance entered successful comparison in the corrected reproduction. This does *not* establish authenticity or chronological external pinning for caller-supplied reference seals.

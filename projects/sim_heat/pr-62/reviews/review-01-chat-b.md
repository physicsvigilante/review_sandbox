### F-01 — **Major, source-identity refusal bypass through public `certify(s)`**

**Source:** [`certified_reference.py` L159–180](https://github.com/physicsvigilante/sim_heat/blob/12bb67e7abac54c8a2488109cb706d779c61bf93/qualification/h1_n1/certified_reference.py#L159-L180), [L183–257](https://github.com/physicsvigilante/sim_heat/blob/12bb67e7abac54c8a2488109cb706d779c61bf93/qualification/h1_n1/certified_reference.py#L183-L257), [L342–349](https://github.com/physicsvigilante/sim_heat/blob/12bb67e7abac54c8a2488109cb706d779c61bf93/qualification/h1_n1/certified_reference.py#L342-L349), [L436–449](https://github.com/physicsvigilante/sim_heat/blob/12bb67e7abac54c8a2488109cb706d779c61bf93/qualification/h1_n1/certified_reference.py#L436-L449).

`read_facts()` correctly checks the raw source-facts bytes and original model/study hashes. However, `certify(s, ...)` accepts **any mutable dict** and immediately calls `construct(s)`; it does **not** validate that its in-memory `s` still equals the authenticated source facts. The output always writes the **hard-coded** `FACTS_SHA256` as `sourceFactsSha256`, even when the object used to compute trajectories is different. Thus the exported provenance claim is not an invariant of the callable that actually certifies. This is especially relevant because tests and likely future integration invoke `certify(s)` directly rather than solely via the pinned CLI.

**Concrete adversarial probe to add:**
```python
s = read_facts()
s["rods"]["T10"]["k"] = Decimal("95.00000000000001")
certify(s, 2400)  # Must REFUSE before computing; currently no source-identity check.
```
Changing `analysis`, boundary facts, rod orientation or exported operands in memory must likewise refuse. This is a *source inspection* counterexample to the missing gate, **not** a claim that a forged full-grid report was personally executed. A very small physically admissible mutation may still pass all interval-error and conservation tests—those validate the supplied *modified* equations, not the original source identity. The CLI route using untouched `read_facts()` remains properly byte-pinned.

**Correction:** place an immutable/equivalence-checked facts binding at the `certify` boundary (or make it load the pinned facts itself); validate the entire admitted physical/analysis/observation identity, not only hash strings carried inside a dict. Refuse mutated in-memory input **before output creation**; add regression tests of physical parameter, orientation, boundary and horizon mutations plus unchanged canonical admission. Do not replace original source facts or references.

### F-02 — **Moderate, nonconservative exponential helper on matrices without the assumed affine zero row**

**Source:** [`certified_reference.py` L131–150](https://github.com/physicsvigilante/sim_heat/blob/12bb67e7abac54c8a2488109cb706d779c61bf93/qualification/h1_n1/certified_reference.py#L131-L150) and [L243–254](https://github.com/physicsvigilante/sim_heat/blob/12bb67e7abac54c8a2488109cb706d779c61bf93/qualification/h1_n1/certified_reference.py#L243-L254).

The Taylor remainder derivation itself is correct **for a general matrix**: `rho^19/19!/(1-rho/20)` encloses the tail once `rho<=1/2`. But `exp_step(b,n)` **unconditionally overwrites its entire final result row with the identity row** after computing that enclosure. It never checks that the last input row of `b` is exactly zero—the necessary premise for the overwrite.

**Decisive analytic counterexample:** `exp_step([[interval(1)]], 2400)` passes the norm precondition, yet forces the sole output interval to **exactly [1,1]**. The actual matrix exponential is `exp(1/2400)>1`, which is outside the claimed interval. Equivalently, for `b=[[0,0],[1,0]]` the true exponential has final-row first entry `1/2400`, but the helper returns zero. These are direct mathematical counterexamples, not an observed failure on the original seven-state case.

**Scope limitation:** the **pinned H1-T1-T `construct` currently makes the last row zero by initialization and only fills rows 0–5**, so this defect does *not* invalidate the present fixed-source propagation. Nevertheless a public, labelled `exp_step` enclosure routine must fail closed outside its documented affine contract; future variants or malformed input could otherwise receive a false certificate.

**Correction:** explicitly require a square matrix of supported dimensions and a **provably exactly zero final row** (both interval endpoints zero), then perform the override; alternatively do not override the enclosure. Add a deliberately nonzero-final-row REFUSAL test and retain the current legitimate seven-state/zero-row positive test.

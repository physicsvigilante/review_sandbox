## Findings and required corrections

### F-01 — MAJOR / DESIGN ACCEPTANCE BLOCKER: external pre-output reference authority is still underspecified

[Migration contract, lines 15–25](https://github.com/physicsvigilante/sim_heat/blob/f0d863e8e1dcc44e89d1ab7e1a2f377d89d9714f/qualification/h1_n3/MIGRATION-CONTRACT.md#L15-L25) correctly *demands* an externally committed reference SHA and semantic seal, two clean replays, host/source binding and a read-only trust anchor independent of generated reference data or caller selection. But it does not make the acceptance authority, immutability and chronology sufficiently testable. A digest placed in an unprotected file outside the attempt just before a launch could satisfy a literal "outside attempt / before output" reading without any independent endorsement. Existing verification cannot prove when or by whom its expected seal was selected; current native preparation self-generates that seal. A matching byte digest and matching *self-chosen* semantic seal are integrity, not externally authorized expected values.

**Required design-level correction, without native work:** specify an authoritative, separately approved expected-manifest contract and its provenance: who can commit/approve it; how the runner authenticates an immutable or protected reviewed revision; proof that the commitment predates any native output; precise binding to candidate source HEAD/tree, checking/reference implementation and version, original model and three study descriptors, all three bundle byte SHA-256s **and** semantic seals, independent full-grid certificate identity, output scales/quadrature/time windows, authorized host/dependency identity, and one-use attempt/approval. Define when the trusted expected manifest is loaded and verified (before any OMC operation), and prohibit replacing it with bundle fields, an attempt-local receipt, a caller-provided "expected" digest or a post-output self-reseal. Require negative controls for stale/unapproved authority, same-attempt reuse, crossed case seals, changed trusted object, post-output sealing and missing independent certificate. The implementation and real external artifact remain future work; the present design needs a non-circular acceptance rule.

### F-02 — MAJOR / DESIGN ACCEPTANCE BLOCKER: versioned runner/bundle transition lacks a normative interface and refusal matrix

The plan names a proposed future checking version and candidate bundle schema, and the prose expressly disallows unknown-version fallback. Those are necessary intentions, but [migration-plan.json#L37-L51](https://github.com/physicsvigilante/sim_heat/blob/f0d863e8e1dcc44e89d1ab7e1a2f377d89d9714f/qualification/h1_n3/migration-plan.json#L37-L51) does **not** yet define an accepted serialized bundle/manifest shape, canonical byte/semantic sealing rules, supported-version dispatch table or exact preflight refusal conditions. This matters because the extant runner explicitly calls old reference.prepare and verification requires reference_bundle/2. Simply adding a new checker while leaving old preparation in the path would silently retain the seven physically failing centres.

**Required design-level correction:** add a compact normative compatibility table/specification for old-versus-new bundle schemas; exact allowed dispatch by externally authorized checking version; immutable code/dependency source closure; deterministic preparation/serialization; per-case references and separate primary/tight/dense identities; explicit checks of *re-prepared* bytes and semantic seals against the F-01 trusted manifest **before execute**; and a refusal matrix for unknown/missing versions, mixed old/new schemas, default/legacy fallback, altered per-output allowances, post-hoc bundle edits and cross-case substitution. State that the new physical certificate is independent and must cover **77 exports, eight public observations, five integrals at each required sample** with all original exact-physical 100x bounds, 64-ULP static native comparison and 0.64-ULP physical reference budget, local K/W/J policy and sealed time/quadrature allowances. Require at least one unfamiliar admitted H1 composition as a future generality test, not just fixed-T1 numerical agreement. This is a *future implementation gate*, not a request to implement or run the runner in PR64.

### F-04 — CONFIRMED / DEFENSIVE PARSER GAP: nonfinite numeric overflow is accepted

[check_migration_plan.py#L53-L66](https://github.com/physicsvigilante/sim_heat/blob/f0d863e8e1dcc44e89d1ab7e1a2f377d89d9714f/qualification/h1_n3/check_migration_plan.py#L53-L66) passes parse_constant=invalid to json.loads but does not reject a finite-syntax exponent that overflows the default float conversion: **{"a":1e309} -> {"a": infinity}**. The existing tests cover NaN and Infinity tokens, not this case. Because N3 requires the entire plan's exact Git blob and does not accept an attacker-supplied alternative plan, **this is not a demonstrated bypass of today's pinned receipt or native refusal**. Nevertheless the broad "nonfinite JSON refused" claim is inaccurate, and the helper must not be carried into an unpinned future manifest parser as-is.

**Correction:** reject nonfinite results from numeric literals (e.g. parse_float with explicit finite-range checks and/or recursive isfinite validation), add positive/negative exponent-overflow, negative-overflow and nested-object tests, and preserve pinned byte/hash and duplicate-key refusals.

### F-05 — CONFIRMED / READ-ONCE WORDING: full check performs two plan-file reads

[check_migration_plan.py#L69-L74](https://github.com/physicsvigilante/sim_heat/blob/f0d863e8e1dcc44e89d1ab7e1a2f377d89d9714f/qualification/h1_n3/check_migration_plan.py#L69-L74) hashes and parses the *same bytes within each read_plan call*; that is sound. However check() calls audit(read_plan()), while [audit()#L102-L105](https://github.com/physicsvigilante/sim_heat/blob/f0d863e8e1dcc44e89d1ab7e1a2f377d89d9714f/qualification/h1_n3/check_migration_plan.py#L102-L105) calls read_plan() again. The CLI therefore reads the plan **twice**, contrary to the reviewer packet's "read-once plan parsing" characterization. Both snapshots must match the fixed known blob, so I found no current authority bypass. Either make one validated snapshot feed the CLI's audit and support safe independent audit callers, or describe the narrower per-call guarantee accurately; test the selected behavior.

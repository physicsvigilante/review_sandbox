## Product goal and exact scope

SIM_HEAT already has a real, restricted H1 admission parser plus a generic viewer for admitted source facts. Previously a teacher had to run H1 admission, separately generate preview JSON, serve the repository, and manually import that JSON to inspect a new supported composition. **PR57 removes that local product friction**, without changing source interpretations: one command performs existing admission and opens the **same existing source-only inspector** with the real admitted model's data loaded by default:

```sh
python -B -m tools.authoring_workbench /path/to/scratch/cases/draft/study.json --root /path/to/scratch/cases
```

On admission it prints a local URL at `http://127.0.0.1:<ephemeral-port>/viewer/source_preview/`. In the *same* unchanged generic viewer, source inputs retain actual study/model identities and SHA-256, original provenance, typed units, logical nodes, and public-request status `not_computed`. It is a **source-only** view, not an original native case, apparatus pose, simulated temperature, native output, or source-textbook authenticity verdict.

**Exactly 5 new files**:
- `tools/authoring_workbench.py`: calls **unchanged** `h1.study.load_study` and `h1.source_preview.build_source_preview` **before any listening socket**; binds only loopback IP `127.0.0.1`; exact route allowlist for reviewed inspector `index.html/app.mjs/core.mjs`, a small help page and the *in-memory* admitted payload. The existing viewer's fixed default `data/TEACH_SPLIT3.json` request is **deliberately a local virtual alias**, not a true identity for any newly authored source; actual study ID and source hashes always come from admitted input. A string-exact HTML text substitution labels custom-session loading truthfully, without modifying checked-in production viewer. Refuse wrong Host, traversal/queries/nonallowlisted files, POST/PUT/DELETE/PATCH, forged source/native metadata (via existing browser), invalid paths/request/attribution/stale source SHA. No local filesystem writes, file upload endpoint, external network bind, compiler, reference generator or native fallback.
- `docs/LOCAL_AUTHORING_WORKBENCH.md`: instructions and reusable LLM-to-two-file authoring request, with explicit H1 grammar limits, source attribution, teacher acceptance checklist and evidence category limits. It does **not** claim autonomous LLM, classroom or blind held-out success.
- `tests/test_authoring_workbench.py`: **six actual tests** with real H1 studies D1, steady S1, TEACH_SPLIT3; typed model/study hash and `not_computed` assertions; negative Host/routes/write method/refused stale hash, unsupported observation and outside-root cases; no source modifications.
- `tests/browser_authoring_workbench.py`: **real HTTP Chromium** default source load for D1 desktop, S1 mobile, TEACH_SPLIT3 desktop, correct source ID/requests, forged qualification refusal clearing previous UI, denied direct `model.mo` and denied HTTP POST, screenshot retention. This is not a local browser result unless reviewer actually runs it.
- `.github/workflows/authoring-workbench-ci.yml`: read-only pinned GitHub Actions with strictly exact five-file allowed diff and protected code/archives/ref unchanged. Full inherited offline suites, original six diagnostic bundle replays, comparison and source-only payload byte equality, original explorer/source-preview/docs real Chromium and new isolated workbench browser smoke. No native operation.

The same builder/inspector is used for **different existing supported compositions** D1, S1 and TEACH_SPLIT3 without apparatus-specific dispatch; developer also personally used a **scratch new composition not committed as an example**: fixed hot boundary→area rod→first finite body→circular rod→second finite body, three observation requests. H1 genuinely admitted it, and the same server generated a preview with 5 components, 2 rods, 3 logical nodes and every request `not_computed`.

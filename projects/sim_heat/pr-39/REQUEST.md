## Motivation and *hard* limitations

Prior reviews PR #36/#37/#38 established that a single textual `maxLaunchesAfterSeparateApproval=1`, CI `GITHUB_RUN_ATTEMPT=1`, local attempt label and unprotected cached branch **do not** guarantee a single native launch across separately started GitHub jobs/hosts or a crash. The owner's actual Option A adoption permits only **offline scientific reference checking** of one exactly saved PR31 mathematical bundle. It is NOT native execution approval.

This new pure-Python `sqlite3` **LOCAL SIMULATOR** tests transaction-level uniqueness and failure semantics on one cooperative local filesystem. `simulate_once(db)` starts `BEGIN IMMEDIATE`, creates a single-campaign table with primary-key constraint and tries `INSERT … ON CONFLICT DO NOTHING`, requiring the same hardcoded reviewed-source/ref/plan identifiers. One worker can record `SIMULATED_LOCAL_SLOT_CONSUMED_NOT_NATIVE`; other cooperative workers attached to the **same actual SQLite file** return `REFUSED_ALREADY_SIMULATED_LOCALLY`. `inspect_only` reads a local record without creating one. A child process crash **after a committed simulated slot** does not free that local row. This is an empirical property of this **local SQLite** test setup, NOT a durable shared external reservation for authorized native work.

**Deliberately tested counterexample to real one-shot:** delete the local database; a new simulated slot is obtainable. A fresh runner/host has its own disk, so independent CI runs also have no common ledger. A malicious actor with write/delete privileges can tamper with the file. The prototype does not authenticate a GitHub owner, protect local storage, attest a host/compiler, invoke a signed ref, prevent all TOCTOU/symlinks under malicious concurrency, or reserve any **actual** native budget. The random local nonce is a demo row identifier, not an owner signing key or execution token. It must never be wired directly to any native launch as an authority.

**Only CLI commands:** `simulate-local-only` and `inspect-local-only`. No `execute`, `build`, `launch`, `native`, `approve`, `omc` or reserve-native action exists. Receipts carry explicit `nativeAllowed=false`, `nativeExecuted=false`, `realAcrossRunReservationAllocated=false`, `ownerNativeLaunchApproved=false`, `releaseTrustRootComplete=false`, `sharedAcrossHosts=false`, `nativeRunnerPresent=false`, `compilerQueried=false`, `buildInvoked=false`, `modelLaunched=false`, `referenceRegenerated=false`, and original F0/PR32 historical success flags false.

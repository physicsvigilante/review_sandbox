## Executive assessment

The core epistemic boundary is well chosen: a detector crossing is observed, its native JS ray reference is matched to either an actual `SingleRay.onSimulationStart().newRays` object or an actual `PlaneGlass.onRayIncident().newRays` child, and only **direct observed parenthood** is claimed. The primary ray is mutated in place; it retains one token. The proposal correctly prohibits `rayIndex`-based source guessing, drawn route history, image detection, irradiance and source-image interpretation claims.

The narrow architecture is preferable to a general ray-history subsystem. A source-only label would lose the proof of an observed distinct Fresnel child and its immediate spawning component. A graph restricted to selected crossings is defensible, provided that the **root-coverage**, **run-epoch** and **raw-evidence suppression** invariants below are made normative. There is no demonstrated production defect in the unimplemented feature.

## Findings

### F-01 — MAJOR — Source coverage is not proven by existing emission counters, especially for a no-hit run

**Evidence:** [proposed failure/empty-result rules, lines 72–77 and 87–97](https://github.com/physicsvigilante/opticsim/blob/df783a3c2f5e51ad5edbacd35f6d82f1a02cfea7/docs/NATIVE-RAY-PROVENANCE-PROPOSAL.md#L70-L97); [production `observeSourceEmission`, lines 75–104](https://github.com/physicsvigilante/opticsim/blob/00e6211d6d40c0db8c62910f9e57b910b6aeb6f5/src/adapter.js#L73-L104); [checker source-state, lines 52–58](https://github.com/physicsvigilante/opticsim/blob/00e6211d6d40c0db8c62910f9e57b910b6aeb6f5/skills/sim-ro-image-to-scene/scripts/check-scene.mjs#L52-L58); [pinned native `SingleRay`, lines 94–106](https://github.com/ricktu288/ray-optics/blob/811f508d2b070898c241a568b0c167dcb8645251/src/core/sceneObjs/lightSource/SingleRay.js#L94-L106).

**Reasoning / counterexample:** Current emission accounting sets `meter.emitted = result?.newRays?.length || 0`; the checker verifies that the sum of *these same observer readings* equals their own aggregate, not an independent native emission count. An installed but silently nonrecording instrument can report zero for a source that actually emitted one object. If the source ray misses all surfaces and the selected detector, there is **no later incident callback** to expose the untagged object. A graph consisting of `nodes:[]` and `crossings:[]` could appear complete even though root instrumentation failed. This is a design risk, **not an observed bug** in PR #81. In the pinned permitted source class, a valid `SingleRay` emits exactly **one** actual new-ray reference on start, regardless of a later miss.

**Required correction:** Define a per-run registration/coverage invariant for **every** authored native source instance before execution. Record that each required start callback was actually invoked exactly once; validate that its returned array has exactly one distinct non-null ray object for the v5 single-ray scope; detect missing, zero, duplicated, re-used and malformed emissions rather than interpreting absent `newRays` as legitimate zero. Compare with independently observable simulator enqueue totals if practicable; never call self-summing per-source meters an independent cross-check. Coverage failure must make even a completed selected-detector miss **unavailable**. The source count and identity check must happen before any empty-graph promotion.

**Novel regression:** Valid one-source / one-interface / one-detector geometry where the ray points away and native detector count is zero. Inject a test-only loss of source identity recording while still delegating the native start callback. Expected provenance `unavailable / PROVENANCE_UNKNOWN_OR_INCONSISTENT`, **not** available empty. Contrast with a genuinely observed one-ray emission followed by a genuine miss, which **must** be available empty.

### F-02 — MAJOR — Specify one atomic instrumentation pipeline and cross-observer invariants

**Evidence:** [proposed lines 73–76, 101–103, 109](https://github.com/physicsvigilante/opticsim/blob/df783a3c2f5e51ad5edbacd35f6d82f1a02cfea7/docs/NATIVE-RAY-PROVENANCE-PROPOSAL.md#L70-L109); [production source/detector wrappers, lines 75–84 and 147–175](https://github.com/physicsvigilante/opticsim/blob/00e6211d6d40c0db8c62910f9e57b910b6aeb6f5/src/adapter.js#L73-L175); [interface wrapper, lines 53–102](https://github.com/physicsvigilante/opticsim/blob/00e6211d6d40c0db8c62910f9e57b910b6aeb6f5/src/planar-media.js#L53-L102); [pinned `Detector`, lines 244–261](https://github.com/ricktu288/ray-optics/blob/811f508d2b070898c241a568b0c167dcb8645251/src/core/sceneObjs/other/Detector.js#L244-L261); [native simulator, lines 933–972](https://github.com/ricktu288/ray-optics/blob/811f508d2b070898c241a568b0c167dcb8645251/src/core/Simulator.js#L933-L972).

**Reasoning / counterexample:** Existing detector observation snapshots pre-mutation values and then delegates once; native `Detector` mutates the ray in place and changes signed power. Existing interface observation records the incoming direction **before** native delegation and outgoing branches **after** it. A second provenance wrapper must hold the **original object reference** across that mutation, and must see actual `newRays` returned by the delegated native call. The design calls for compositional wrappers but does not yet define the mandatory wrapper ordering and single-delegation observation point. Accidental double delegation changes native trajectories, sample events or power; double wrapping can count a single child twice.

**Required correction:** Prefer integrating identity capture into the existing per-instance source/interface/detector observer composition, or specify one rigorously ordered wrapper chain, installed exactly once before `onSimulationStart`. Assert the same native input ray reference, incident arguments, return-object identity and child references, one delegated original call per event, no changes to array order or `pendingRays`, and no propagation from the observer. Treat duplicate/cyclic/reused children and unobserved incident parents as `unavailable` for the whole requested result, never as a second root. Cover both selected and other authored detectors; preserve existing signed power, counts, interface first-event and raw positional-event behavior.

**Novel regression:** Two sources that hit the same interface and separate detectors, then reverse source/component ordering; compare wrapped and unwrapped runs including all emissions, processed segments, truncation, undefined behavior, every detector's count/power, interface first-event, and new direct parent edges. Inject a returned child reference equal to the parent and a duplicated returned child reference (test-only wrapper fault); both must refuse without altering physics. Verify default/no-opt-in byte/shape compatibility.

### F-03 — MAJOR — Define provenance suppression across *all* public surfaces and all run revisions

**Evidence:** [proposal lines 87–95 and 101–104](https://github.com/physicsvigilante/opticsim/blob/df783a3c2f5e51ad5edbacd35f6d82f1a02cfea7/docs/NATIVE-RAY-PROVENANCE-PROPOSAL.md#L85-L105); [diagnostics gating for older hit-event capture, lines 197–217](https://github.com/physicsvigilante/opticsim/blob/00e6211d6d40c0db8c62910f9e57b910b6aeb6f5/src/adapter.js#L197-L217); [public summary, lines 30–55](https://github.com/physicsvigilante/opticsim/blob/00e6211d6d40c0db8c62910f9e57b910b6aeb6f5/scripts/author-scene.mjs#L30-L55); [observable hash gate, lines 65–82](https://github.com/physicsvigilante/opticsim/blob/00e6211d6d40c0db8c62910f9e57b910b6aeb6f5/src/observables.js#L65-L82); [Session revision guard, lines 19–44](https://github.com/physicsvigilante/opticsim/blob/00e6211d6d40c0db8c62910f9e57b910b6aeb6f5/src/session.js#L19-L44); [QualifiedUI async revision/sequence check, lines 152–161](https://github.com/physicsvigilante/opticsim/blob/00e6211d6d40c0db8c62910f9e57b910b6aeb6f5/src/qualified-ui.js#L152-L161).

**Reasoning / counterexample:** The proposal correctly requires that stale, failed and incomplete native attempts withhold the full graph, including diagnostics. This needs an explicit contract boundary: currently CLI processing can publish `run.native.diagnostics` separately from the qualified `summary.observations`; hiding only `results[].value` or `summary.observations` would leak unfinished raw graph fields. Hash equality alone also cannot distinguish run A from a later run A after an A → B → A edit sequence. Existing `Session` and `QualifiedUI` *already* have revision/sequence guards; a new capture path must preserve these rather than trusting only the scene hash.

**Required correction:** Declare graph/event metadata private until **both** the native terminal event and all qualification checks succeed, then project only the qualified opt-in result. On failed/stopped/truncated/undefined/stale/warning/unknown/overflow conditions, no public `nodes`, `crossings`, or raw graph/parent map may appear in checker diagnostics, CLI report, browser state, qualified export or debug snapshot. Pass a run-instance/revision identity through any asynchronous browser result publication; retain the existing Session/QualifiedUI sequence guards. A same-hash rerun should generate independent ephemeral tokens, not silently borrow a prior run's object mapping.

**Novel regressions:** Inspect *whole public JSON/report/browser surfaces*, not just observable result status, for a Fresnel truncation and a forced stop. Then test A → B → A with delayed completion from the first A and an independent fresh A run. Old callback must not publish a graph for current A even though its canonical hash matches. Raw scene import must clear qualification.

### F-04 — MINOR — Resolve native-warning versus declared-approximation status rules

**Evidence:** [proposal fail-closed table, lines 89–95](https://github.com/physicsvigilante/opticsim/blob/df783a3c2f5e51ad5edbacd35f6d82f1a02cfea7/docs/NATIVE-RAY-PROVENANCE-PROPOSAL.md#L85-L95); [existing observable warning construction, lines 70–75 and 103–105](https://github.com/physicsvigilante/opticsim/blob/00e6211d6d40c0db8c62910f9e57b910b6aeb6f5/src/observables.js#L70-L105).

**Reasoning:** The design says **any native warning** makes provenance unavailable, but allows `qualified` for the explicit `partialReflection:false` transmitted-only approximation. These are different warning sources and should be explicitly kept separate. A native warning must not become a `qualified` success just because a documented model approximation also exists. Conversely, an otherwise clean Fresnel-off run need not be refused merely because the authored approximation has a mandatory explanatory caveat.

**Required correction:** Specify status precedence: incomplete/stale/failed → `suppressed`; native-run warning or observer inconsistencies or scope/cap failures on completed runs → `unavailable`; clean completed run with a *declared model-only approximation caveat* → `qualified`; clean completed full-model run → `available`. Publish machine-readable reasons on unavailable/suppressed states and retain the approximation limitation on qualified states. Consider separate stale and incomplete reason codes if downstream automation needs to distinguish remediation.

### F-05 — MINOR — The 64-object / 32-hit tests are guard tests, not attainable ordinary v1 physics coverage

**Evidence:** [one-interface / 1–2 single-ray scope, lines 19–28](https://github.com/physicsvigilante/opticsim/blob/df783a3c2f5e51ad5edbacd35f6d82f1a02cfea7/docs/NATIVE-RAY-PROVENANCE-PROPOSAL.md#L19-L28); [limits and acceptance, lines 91–97 and 115](https://github.com/physicsvigilante/opticsim/blob/df783a3c2f5e51ad5edbacd35f6d82f1a02cfea7/docs/NATIVE-RAY-PROVENANCE-PROPOSAL.md#L89-L115); [native `SingleRay` output](https://github.com/ricktu288/ray-optics/blob/811f508d2b070898c241a568b0c167dcb8645251/src/core/sceneObjs/lightSource/SingleRay.js#L94-L106); [native Fresnel path](https://github.com/ricktu288/ray-optics/blob/811f508d2b070898c241a568b0c167dcb8645251/src/core/sceneObjs/BaseGlass.js#L210-L285).

**Reasoning:** Under the nondegenerate first-release geometry, at most two primary single-ray objects are emitted; each can undergo one planar interface encounter and create at most one reflected child, so **at most four legitimate distinct ray objects**. Passive finite detectors create no rays. The ordinary native v1 physical domain therefore cannot naturally exercise 64/65 identities or 32/33 selected hits. Numerical pathologies or injected callbacks may exceed these counts, but that is not ordinary qualified source coverage. The caps are reasonable defensive bounds; the requested boundary tests need a different evidentiary label.

**Required correction:** Make the component allowlist explicit: *exactly* one v5 planar-interface, 1–2 `point-source/single-ray`, 1–2 passive `ray-detector`, and **zero other component types**. Retain 64/32 as conservative fail-closed guardrails, but test their 64/65 and 32/33 boundaries with separately labeled **test-only injected callback streams**, not an unsupported fan, mirror, second interface or invented ordinary-v1 native scenario. Never expand scene scope merely to hit a cap. Specify whether overflow on a nonselected detector may coexist with a complete selected-detector graph, and whether simultaneous two-detector requests share a single run-wide token registry (they should).

### F-06 — MINOR / PHYSICAL SCOPE CAUTION — Native identity and critical-angle physical correctness must never be conflated

**Evidence:** [proposal lines 28, 74–78, 110–111](https://github.com/physicsvigilante/opticsim/blob/df783a3c2f5e51ad5edbacd35f6d82f1a02cfea7/docs/NATIVE-RAY-PROVENANCE-PROPOSAL.md#L28-L28); [pinned native Snell discriminant, TIR and reflected-child behavior, lines 204–283](https://github.com/ricktu288/ray-optics/blob/811f508d2b070898c241a568b0c167dcb8645251/src/core/sceneObjs/BaseGlass.js#L204-L283); [PR #80 research run](https://github.com/physicsvigilante/opticsim/actions/runs/43729455968).

**Reasoning / independent numerical reference:** For n(high)=1.5 to n(low)=1, critical angle is `asin(2/3) = 41.8103148957786°`. At 30° incidence, Snell gives `48.5903778907291°` transmission; at 50°, total internal reflection. For 1 → 1.5 with 30° incidence, transmission angle is `19.4712206344907°`. These are separate analytical computations by this reviewer, **not native simulations**. The native discriminant `sq1 < 0` decides TIR; floating-point values at exactly critical can fall on either side and change whether reflected light is represented by the mutated primary or a newly returned child. In the inspected PR #80 raw artifact, the `critical-exact` native case completed with no returned child; this verifies only its observed object identity, not exact-critical physical fidelity.

**Required correction:** Keep near/exact-critical provenance explicitly **native-identity-only**; exclude those cases from any physics-qualified statement that the selected detector must/should be reached. Prefer mark critical-angle *physical inference* indeterminate, or defer teacher-facing critical-angle conclusions until a separate numerical qualification. Native provenance alone must not be presented as a complete ray path, actual optical image, true material-index inference or continuous visibility.

### F-07 — MINOR — Make the educational limitation machine-readable and preserve run-local token semantics

**Evidence:** [proposed value and semantics, lines 44–79](https://github.com/physicsvigilante/opticsim/blob/df783a3c2f5e51ad5edbacd35f6d82f1a02cfea7/docs/NATIVE-RAY-PROVENANCE-PROPOSAL.md#L44-L79); [existing detector hit-event limitations](https://github.com/physicsvigilante/opticsim/blob/00e6211d6d40c0db8c62910f9e57b910b6aeb6f5/docs/DETECTOR-HIT-EVENTS.md#L35-L76).

**Reasoning:** A node `source → child@AirWater` is **not** evidence of every intervening interface encounter, geometric continuity or the exact branch type at the detector. For a transmitted primary or TIR-in-place ray there is no new graph edge at all; absence of an edge cannot imply absence of an interaction. Native hit-event and provenance arrays cannot be paired merely by equal lengths or callback ordering unless captured in one reviewed callback.

**Suggested correction:** Use `method: "native-observed-object-parentage"`, an explicit limitation equivalent to “direct observed object parenthood only; same-object interactions absent; no path/image/continuous illumination inference,” and a run-local token namespace. The example `nodes` + `crossings` shape is otherwise a reasonable bounded output and need not grow a route-event engine.

## Release advice / smallest next step

**Keep PR #81 draft and unmerged.** Before giving Chat A permission to implement, revise its design document to make F-01, F-02 and F-03 explicit normative invariants and clarify the status precedence and cap-test semantics in F-04/F-05. The essential correction is to treat a *legitimate empty crossing result* differently from a run in which even one permitted `SingleRay` emission was not properly observed, including when there are **zero downstream callbacks**.

Then bounded implementation can be authorized *separately by the owner*, without changing native PhyDemo, geometry scope or adding a general ray-history engine. The minimum new release tests should be: (a) valid clean zero hit versus zero-hit lost source, (b) one clean two-source Fresnel/dual-detector parent graph plus wrapped/unwrapped exact native comparisons, (c) in-place TIR versus Fresnel spawn with independent Snell numbers and critical caveat, (d) injected duplicate parent/child and cap boundary refusal, (e) forced incomplete/stop and public-report non-leakage, and (f) browser edit/rerun A → B → A stale-token suppression. The future implementation requires full exact-head CI, focused native/browser evidence, a **new** independent R2 implementation review and explicit owner merge approval.

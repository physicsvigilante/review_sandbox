**Independent continuous-field derivation.** Let `A=1.5`, `L=1 mm`, `u=y-axisY` and `n²=A+u/L`. Translation symmetry in x gives the conserved first integral `n cos(theta)=sqrt(A)` for a horizontal ray starting at `u=0`. Thus
```text
dy/dx = sqrt((n(y)^2/A)-1) = sqrt(u/(A*L))
u(x) = (x-sourceX)^2 / (4*A*L).
```
At a vertical exit `xR`, the normal-tangential Snell invariant gives `nOutside*sin(thetaOutside)=(xR-sourceX)/(2*sqrt(A)*L)`. In free space from `xR` to detector `xD`,
```text
yD = axisY + (xR-sourceX)^2/(4*A*L)
   + (xD-xR)*s/sqrt(1-s^2),
s = (xR-sourceX)/(2*sqrt(A)*L*nOutside).
```
This matches the source's [`grinV25ExactReference`](https://github.com/physicsvigilante/opticsim/blob/a05e4ac88afcd23e17fe07c4be8c8076b5c628c3/src/native-grin-v25.js#L42-L59) and its physical-y versus native-y sign convention. For the baseline `sourceX=0.1`, `xR=1.0`, `xD=1.2` mm, my independent calculation yields exit physical `y=0.135` mm and expected detector physical `y=0.214011230635` mm. Native hit: `y=0.213563115132` mm, discrepancy `0.000448115503` mm.

## 8. Nonblocking qualifications and owner-facing conditions

1. **Bounded accuracy only.** The 0.002 mm decision is an observed deviation threshold along this single supported horizontal inside-source ray and external detector. It is not an interval error bound, guarantee for unobserved paths, arbitrary geometries, grazing rays, or all gradient profiles. Retain this qualification explicitly in user-facing language; the current v25 UI does so.
2. **Diagnostic versus qualified output.** On failure the guard's *raw diagnostic* object can still record a native event point. Its `status='withheld-uncertain'` and canonical failed run must remain authoritative: never promote that raw diagnostic point into a measured requested result, portable qualified bundle or completed scene display. Existing public result paths correctly suppress it; consider an additional regression specifically covering any **future** consumers of these debug fields.
3. **Visual scope.** The renderer's lengthScale adjustment intentionally changes glyph sizes and rendering samples at extreme zooms. It changes **visual presentation**, not Scene.lengthScale or native physics. Keep this per-instance v25-only adapter, and do not generalize it to historical renderer modes without separate evaluation. The current final Chrome visual is faithful for the admitted example.
4. **Evidence limits.** This review inspects exact pinned source, native implementation, final CI job logs, downloaded artifact checksums, native records and real-browser screenshots, but **does not claim a separate independent native/Chrome execution**, a textbook-source correctness review, a public deployment check, or old standalone physics recertification.

These are **scope and future-hardening notes, not changes required before the owner makes the release decision**. There is no evidence-based blocker requiring an amended PR head.

## Code and geometry audit

1. **Canonical emission:** [`src/parallel-beam.js` lines 18–40](https://github.com/physicsvigilante/opticsim/blob/05385e3daefaffcfc56fb072a12ba81dd6432993/src/parallel-beam.js#L18-L40) builds a finite emitting segment perpendicular to the authored heading and compiles a literal native `Beam`, not a point-source substitute. The world y-up endpoints are individually flipped into native y-down; brightness is passed through, with `emisAngle:0`, `lambert:false`, `random:false`. The [`adapter`](https://github.com/physicsvigilante/opticsim/blob/05385e3daefaffcfc56fb072a12ba81dd6432993/src/adapter.js#L16-L61) dispatches the true compiled source.
2. **Strict, isolated composition:** [`composition-profiles.js` lines 74–82, 89–101](https://github.com/physicsvigilante/opticsim/blob/05385e3daefaffcfc56fb072a12ba81dd6432993/src/composition-profiles.js#L74-L101) reserves exactly two v19 profiles: one Beam plus at most one ideal lens/one vertical centred-gap stop, OR one Beam plus one/two consistently oriented planar interfaces, with 0–2 passive detectors. `compositionCountsMatch` forbids extra source/optic types, including point-source substitution; no permissive fallback is attempted after rejection. The [`contract`](https://github.com/physicsvigilante/opticsim/blob/05385e3daefaffcfc56fb072a12ba81dd6432993/src/contract.js#L65-L120) keeps the beam type inadmissible for v1–v13. Unreserved v14–v18 are not implicitly admitted.
3. **Whole-segment boundaries / requested counterexample:** For lens and stop planes, both emitting endpoints must be on the same side of the relevant x-plane by at least 0.01 mm (`outsidePlane`). For every planar medium interface, the signed normal distances of **both** endpoints must exceed 0.01 mm in absolute value and have the same sign. Signed distance along a straight line segment interpolates affinely between its endpoints. Therefore an *interior emitter crossing* of any admitted initial optical/medium supporting plane cannot satisfy those rules. Detector supporting-line signed distances are checked analogously. I found **no counterexample passing these explicit checks that starts the emitting segment across a supported optical or medium boundary**. This is a source-geometry argument, **not** an independent native execution or proof about floating-point secondary optical encounters.
4. **Bounded corners and shared media:** [`parallel-beam.js` lines 75–130](https://github.com/physicsvigilante/opticsim/blob/05385e3daefaffcfc56fb072a12ba81dd6432993/src/parallel-beam.js#L75-L130) checks emission endpoints, initial midpoint-sampled paths against lens rim and stop/gap corners, normal separation, same-normal planar interfaces, matching adjacent absolute indices and whole-detector single-medium placement. The [`planar-media` compiler](https://github.com/physicsvigilante/opticsim/blob/05385e3daefaffcfc56fb072a12ba81dd6432993/src/planar-media.js) converts signed indices into native `PlaneGlass` ratios. It does not invent optical paths. The initial-corner guard does *not* guarantee the location of a subsequent refracted encounter; the v19 scope explicitly disclaims this.
5. **Sampling, observer delegation and readouts:** ray density is a separate numeric control; the validator refuses zero/over-100 samples and `brightness > rayDensity`. [`observeSourceEmission`](https://github.com/physicsvigilante/opticsim/blob/05385e3daefaffcfc56fb072a12ba81dd6432993/src/adapter.js#L75-L111) delegates to the original native `onSimulationStart` **exactly once** and observes native newRays rather than sampling replacement rays. Detector observers delegate their original incident once. On overflow, 32-position event lists become unavailable while original detector crossing counts remain intact. [`evaluateObservables`](https://github.com/physicsvigilante/opticsim/blob/05385e3daefaffcfc56fb072a12ba81dd6432993/src/observables.js#L71-L94) suppresses **every requested quantity** if native execution is incomplete or the scene hash is stale. The v19 source does not silently acquire the older point-source `ideal-image` measurement.

## Findings, severity and follow-up

- **P0 — none identified. P1 — no demonstrated blocker for this bounded isolated candidate.** No source/medium-start straddle was found in the admitted geometry; no evidence of native ray substitution, fabricated focal arrival, partial Fresnel readout leakage, or old-version admission was found in the reviewed code and archives.
- **Nonblocking N1 — integration dependency, before any production merge:** v19 intentionally skips unmerged v14–v18. PR #127 is tested against the research parent/main lineage, **not** an assembled future v14–v19 release tree. Reconcile registry/schema/profile changes, rerun all native and historical save tests and obtain a new combined review when owners choose an integration order.
- **Nonblocking N2 — secondary-corner/numeric policy:** the sample-to-stop/lens corner test is an *initial straight-path* admission guard, not a post-lens collision guarantee. E.g. with a lens at x=0, f=100 and a downstream stop at x=50, a ray initially at y=17.5 crosses the later stop at y≈8.75; a centred 17.5 mm opening could put that refracted ray at a gap endpoint despite a safe *initial* source-to-stop test. Treat such encounters as unqualified if native ambiguity occurs; add a targeted downstream-corner regression. The near-grazing rejection uses an extremely narrow `|normal·direction| <= 1e-8` threshold; document this quantitative limit or test finite off-axis near-grazing behavior explicitly.
- **Nonblocking N3 — unexercised but admitted starting-media/heading arrangements:** current v19 end-to-end source tests focus on left-to-right air→slab, horizontal forward lens and one high→low TIR setup. Before widening claims, run independently authored canonical v19 tests with the emitter initially *inside* the middle slab medium, beyond both interfaces and propagating in reverse, and with both `+180`/`−180` lens headings. The prior #126 test-native reverse Beam supports feasibility but is not identical to full public v19 authoring.
- **Nonblocking N4 — simulation controls clarity:** public `preview-v1` and `dense-v1` policies pin `maxRayDepth=8` and `processedRayLimit=10000`, but the canonical validator still accepts manually edited v19 `maxRayDepth` from 0 to 8 and smaller processed limits. Decide explicitly whether direct canonical saves may override those limits; do not interpret a lower-depth trace as the standard v19 policy. This is an interface-contract clarification, not a demonstrated wrong native result.
- **Scope limitations:** these are synthetic JEE-*style* controls, with no scored original JEE textbook problems, no verified interpretation of a real illustration, no image/PSF, 3D optical wavefront, diffraction, radiometric calibration, lineage through arbitrary optics, or general composability beyond the two admitted profiles. Fresnel-off is an explicit transmitted-only approximation, with native TIR retained.

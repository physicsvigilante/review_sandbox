## BLOCKER B1: v26's sample-safety witness can omit a real native Beam sample

**Affected source:** [v26 witness](https://github.com/physicsvigilante/opticsim/blob/9a2887f7cc5396387575fca1d6600e7a20b7f825/src/native-beam-planar-mirror-v26.js), [shared `parallelBeamSamples`](https://github.com/physicsvigilante/opticsim/blob/9a2887f7cc5396387575fca1d6600e7a20b7f825/src/parallel-beam.js), and pinned upstream [`Beam.onSimulationStart`](https://github.com/ricktu288/ray-optics/blob/811f508d2b070898c241a568b0c167dcb8645251/src/core/sceneObjs/lightSource/Beam.js) / [`geometry.segmentLength`](https://github.com/ricktu288/ray-optics/blob/811f508d2b070898c241a568b0c167dcb8645251/src/core/geometry.js).

The necessary first-mirror-hit clearance checks `parallelBeamSamples(beam,rayDensity)`. This helper sets `n = beam.width * rayDensity` and emits for `i = .5; i <= n; i++`. However the **actual pinned native Beam** uses `n = geometry.segmentLength(this) * rayDensity / scene.lengthScale` and the same half-integer loop; `geometry.segmentLength` computes `Math.sqrt(dx*dx + dy*dy)` from the compiled floating-point segment endpoints. The scene's archived native `lengthScale` is 1. At half-integer sample thresholds, floating-point endpoint construction can put these two values on opposite sides of the comparison. The admission witness can consequently check one fewer sample than PhyDemo emits.

**Concrete bounded reproduction using the exact formulas (without modifying repository code):**

- Beam `x=-100, y=0, width=50, directionDeg=1, brightness=.08`; density `0.29`; interface `x=0, normalDeg=0, negativeIndex=1, positiveIndex=1.5, partialReflection=false`; vertical mirror `x=60, y=4, length=48, orientationDeg=90`; optional source-side vertical detector `x=-10, y=0, length=420, orientationDeg=90`.
- Compiled emitter endpoints from the checked-in geometry: `p1=(-100.43631016093208, 24.996192378909782)`, `p2=(-99.56368983906792, -24.996192378909782)`.
- Witness `width*density = 14.499999999999998` ⇒ **14** checked samples. Native `sqrt(dx²+dy²)=50.00000000000001`, giving `native n = 14.500000000000002` ⇒ **15** native emissions in the pinned half-integer loop.
- All **14 witness-predicted** first mirror hits lie between `y=-19.111357063536563` and `y=25.72305764187999`, safely inside the authored mirror's `[-20,28]` extent by more than 0.1 mm. Other listed v26 geometry, ordering, index, source, brightness and detector constraints are satisfied.
- The **15th native** sample's independent refracted first-mirror intersection is `y≈-22.560158194722447`, below the finite mirror bottom `-20`. Therefore an apparently admitted configuration violates the intended all-actual-samples mirror-interception invariant. Moving the mirror endpoint to within 0.1 mm of this additional ray similarly creates an unguarded near-rim case.

This is not a paper-ray injection or an assertion of a newly executed native run: it is a deterministic discrepancy in the **actual pinned native emission count formula** versus the **new admission witness formula**. The candidate's existing tests exercise integral sample counts (e.g. 8, 16, 40), not this half-integer boundary. The consequence is material even if the native engine correctly reports a miss: v26 claims every actual emitted ray is pre-screened from unsafe finite mirror ends. Native completion alone does not prove that claim.

**Required correction before clearance:** derive the admission samples from the exact compiled native Beam endpoints and exact native `geometry.segmentLength`/density/lengthScale arithmetic, or conservatively refuse ambiguous half-integer sampling thresholds. Verify the witness and native emitted count/positions at and on both sides of half-integer thresholds, including translated/oblique beams; include this concrete 50-mm, 1°, density .29 case with a shortened mirror and a near-rim mirror negative control. The v26 validator must refuse/guard every **actual** sample, not just `width * density` samples. Preserve native ray tracing and all existing old-profile behavior.

## Nonblocking limitations and follow-ups

- v26 is narrow: native sampled **2D** rays, one flat interface, one finite vertical mirror, optional passive source-side detectors, 0–60° forward Beam, explicit absolute indices with second ≥ first. `partialReflection:false` deliberately suppresses Fresnel partial branches; native TIR remains. No physical irradiance, image/PSF, continuous beam, source-lineage or original J08 answer is certified.
- The archived **edited** qualified Chrome export correctly records physical width `20` and index `1.8` and maintains an edit ledger, but its retained *author-provided interpretation prose* still says “Beam width 40 mm.” This is stale explanatory metadata, explicitly labelled as not independently verified. Consider warning/reconciling these assumptions on physical edits; do not confuse them with the authoritative physical scene.
- Additional conservative edge cases worth adding after B1: near-exact half-integer native emissions at other angles/offsets; equal-index control; two source-side detectors; a near-rim **actual** native callback rather than only a raw missed mirror. These are focused v26 tests, not requests to review unchanged v5/v19 propagation or reopen other optics.

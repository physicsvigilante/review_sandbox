
Only for already valid existing **v9 `polygon-dielectric-tracing`** scenes with exactly one strict convex four-vertex Glass, 1–4 explicit native SingleRay sources, 0–2 existing external detectors, zero other optical components. It uses the **already-installed original per-native-instance source, Glass and detector observation owners**, exact authored/native ID/method coverage and one native Glass original call. It snapshots ray p1/p2 and incident point as binary64 scalars **before native mutation**, retains at most 128 snapshots and counts every callback even after cap. **No fabricated tolerance:** Without a justified, independently validated point agreement error envelope, any nonzero difference between exact represented intersection `P*` and native reported incident point is **unknown**, not `checked`, unless other exact forward/finite/cutoff contradiction is already independently proven. Both computed and native-reported near-vertex cases remain unknown. Robust nonforward / subcutoff / outside finite-segment evidence gives `inconsistent`. Valid zero-hit with positive source/emitter/observer coverage is `checked-no-hit`; 129th hit, unknown source identity, bypassed hooks or native warnings give `unknown`; incomplete/truncated/failed/stopped are `suppressed`.

**The diagnostic itself is NOT a verified physical observable.** It is returned with public `status:'advisory'` and safe counts/reason/limit, never raw incident ray endpoint lists, paths, an accepted image, source-authenticity claim or absolute irradiance. Its method is `advisory-native-finite-hit-binary64-v1`. Existing `detector-crossings`, `detector-signed-power`, `interface-*`, source and Fresnel readouts are **not changed, withheld or newly qualified**. Even `checked` merely says a bounded necessary binary64 geometric consistency condition passed; it does not certify optics. A detected contradiction triggers a conspicuous **NOT independently certified by this advisory** warning in ordinary result and evidence panels. The normal `resultCoverage.available` deliberately does not count `advisory`, so a problem request containing only this diagnostic may return process exit **2** despite a complete native run and advisory produced. No default outputs include `finiteHitDiagnostic` unless the request explicitly opts in.
